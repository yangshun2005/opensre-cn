# 终端 UI 设计指南

适用于此 UI 目录树。仓库根目录和上级 `AGENTS.md` 的规则仍然适用。
相关的 CLI 和共享终端展示变更也遵循这些约定；实现放在其所属的包中，不一定放在本文件夹。

## 复用现有展示层

- 记录式列表使用 `surfaces/shared/terminal/tables/records.py` 中的 `RecordTable`、`RecordColumn` 和 `RecordRow`。不要为每个命令重复实现列宽计算、断点或堆叠行渲染。
- 带间距的摘要文本使用 `surfaces/shared/terminal/tables/descriptions.py` 中的 `description_details`。领域特定的格式化保留在其所属的渲染器中；命令处理器专注于解析、获取和分发。
- 在契约一致的地方，CLI 和 REPL 共享展示逻辑。不要引入另一个通用框架，也不要强行将非记录视图塞进表格。

## 可编辑的命令输入

- 可编辑的 CLI/REPL 表单复用 `surfaces/shared/terminal/components/input_form.py` 中的 `build_input_form`、`InputField` 和 `InputChoice`。不要复制命令的 prompt-toolkit 布局、导航或编辑状态机。
- 字段定义、默认值、条件可见性和领域校验保留在所属命令的 UI 模块中。参考 `ui/work_input.py` 和 `ui/cron_input/form.py`。可操作的错误使用 `InputFormError`，能重新打开时附带字段名。
- 共享组件负责文本/选项/搜索编辑、可读描述、紧凑审核、更多选项以及固定的提交/取消操作。字段定义在接受编辑后刷新，而非每次重绘时刷新；外部设置按表单/配置键解析一次，不要在渲染时读取凭据。
- 校验必须无副作用。仅在显式提交后持久化；取消不得保存。使用 `run_command_input` 管理终端生命周期，并保持独占 stdin 所有权、完整命令绕过和非 TTY 行为。
- 提交时检查条件完整性，允许临时空编辑，以便依赖字段一起清空。局部值约束使用字段级校验器，不要使用依赖上一稿其他字段的规则。

## 层级与间距

- 名称/标题加粗并作为主要信息。描述和普通结果使用 `SECONDARY`；ID、辅助元数据、时间戳和提示使用 `DIM`。
- **输入表单约定：** 字段描述、示例以及必填/可选/默认标记必须保持可读。使用 `SECONDARY`（共享命令输入的 `description` 样式）或 `TEXT`；填写字段所需的信息绝不使用 `DIM`/`hint`。`DIM`/`hint` 仅保留给键盘快捷键和三级元数据。字段标签保持主要样式，错误使用其语义错误样式。在 CLI、REPL 和共享终端表单中一致应用此规则。
- 不要让所有字段同等暗淡：描述必须保持可读。保留错误、警告、运行进度以及 **Invalid**、**Failed**、**Blocked** 等状态的语义强调。绝不要全局静音诊断信息。
- 使用 `infrastructure/terminal/theme.py` 中的令牌，不要使用内联颜色。构造具体的 Rich 文本样式时，用 `str(token)` 解析惰性令牌。通过字重和颜色表达层级，不要按行设置终端字号。
- 外层水平内边距使用两个终端单元格，摘要列之间使用四个单元格。列宽按显示内容确定；不要将短字段拉伸到整个屏幕，也不要为了保留表格而压缩间距。
- 将完整 ID 放入 `RecordRow.metadata`，在一个空行后对齐到主列下方。Channel、TZ 和有值的 Project 保留在摘要列中，不要挤到 ID 行上。省略全空的可选列。ID 不得参与摘要列宽计算。
- 辅助详情和描述在外层内边距基础上再缩进两个单元格。窄屏下优先显示名称和 ID，然后是分隔的带标签字段。根据实际列宽加间距选择堆叠输出，而非固定终端断点。超长名称保持可读的换行。
- 非空摘要上方留一个空行，记录之间留一个空行。由 `description_details` 和 `RecordTable` 提供这些间距；不要重复添加。空描述不得产生空摘要块。

## 响应式输出与有界预览

- 宽屏下摘要列保持紧凑并靠左分组，不要将元数据拉伸到终端右边缘。让共享渲染器在渲染/重放时重新计算几何布局，以便调整大小后仍然正确。
- 窄终端下使用带标签的堆叠记录。长 ID 和描述放在可重排的详情行中，不要放在微小列或不换行单元格中。
- 列表预览按终端单元格宽度限制，而非 Python 字符串长度。共享描述辅助函数默认 80 单元格并带省略号；视图现有契约要求时使用显式限制。规范化摘要空白。
- 截断必须提供可用的完整内容访问路径：例如 `/memory show <name>`、`/loops show <id>`、`opensre cron logs <task_id> --run <Run>` 或 `opensre --json cron list`。在该目标处保持完整详情不变。
- 保留完整的可操作标识符和时区上下文。没有完整详情目标时，不要截断工作排名原因；允许其换行。存储/用户文本使用 Rich `Text` 渲染，或在标记前转义。

## 减少噪音而不丢失信息

- 保留列表行以便扫视。将冗长的恢复说明移到详情视图，但在列表中保留失败状态和清晰的导航提示。
- 省略缺失的元数据（如 `Project: —`）、重复的命令/摘要文本，以及存在显式 `path` 命令时的常规存储路径页脚。保留合法的零值和有意义的状​​态；不要一刀切隐藏字段。
- 保留隐私警告（如记忆以未加密方式存储）。缩短措辞而非删除；保持管理/帮助路径可发现。
- 打磨展示时保留 JSON 输出、存储数据、执行语义和完整报告内容。不要从散文中的关键词推断失败；使用结构化状态选择警告/错误样式。

## 菜单与验证

- 根命令打开子菜单时，将其默认列表操作作为显式的第一个 `list` 选项暴露。在支持的地方保留现有的裸命令分发，并保持处理器、补全、用法和目录元数据同步。
- 遵循父级的 stdin 规则。在 `runtime/input_policy.py` 中注册确切的表格生成子命令；裸命令预留不覆盖别名。使用既有的 REPL 渲染包装器，以便转录记录/重放正常工作。
- 对于可见变更，在窄宽度（40 列）、典型宽度（80–100）和宽宽度（160 或以上）下检查实际输出。检查长/Unicode 名称、字面标记、空数据、缺失描述和失败状态。
- 为信息丢失、预览限制、间距和完整详情访问添加针对性的回归测试。对于菜单/stdin 变更，走真实 PTY 流程并在后续提示中输入，以捕获泄漏的 CPR 字节或损坏的编辑。
- 在 PR 的 Demo 部分放置当前的前后对比证据，使用隔离的合成数据。区分实际截图和设计预览；验证图片可加载。不要仅为托管演示截图而将其提交到源码或 `docs/`。验证遵循 `CI.md`；本指南不新增第二条 CI 流水线。
