# CI/CD 入门

本主技能负责入门问题。宿主在进入时打开其菜单；结果的 `entry_menu` 会报告是否已打开。若当前消息已作答，直接进入所选子技能。同一请求绝不重复询问入门问题。

## 询问用户

在决定操作前先读取 `entry_menu` 结果：

- `menu: queued`：结束本轮，等待选择。菜单由宿主管理；不要再次调用 `ask_user_choice`，也不要以文本形式重复其选项。
- `menu: suppressed`：未打开新菜单。使用已有答案继续当前请求。若用户明确再次请求演示菜单，调用 `slash_invoke` 并传入 `/demo`；问候语不构成重新打开的请求。
- `menu: unavailable`：以编号列表展示当前演示选项，并等待回复。
- 无菜单状态的 Hook 错误：说明选择器无法打开，并以编号列表展示当前演示选项。

只有排队中的菜单才可告知用户从已打开的选择器中选择。菜单没有自由文本行。其最后一项打开纯 Shell；Shell 处理 Skip 和 Escape，不向模型发送答案。

## 跟随所选子技能

下一条消息携带问题与用户的答案。本地或云端修复还可能携带对 `Create a private demo repository?` 的第二个答案。该答案即目标决策。不要再次询问，也不要重新打开本菜单。调用 `skill_view` 并传入匹配的名称，然后在同一轮中遵循其返回的指令：

使用下方生成的当前演示选项，将答案匹配到对应技能。在执行其工作流前先加载该技能。

对于自定义答案，将该文本视为用户请求，并使用合适的工具或技能处理。不要重新打开本菜单，也不要强制选择某个演示。子技能提出自己的问题后，继续该子技能，而不是返回本主菜单。Escape 取消入门；等待新的用户请求。

显式 `/demo` 会以新请求启动所选工作流。让其工具解析已有的活跃运行；已完成的结果不计为新运行。

当选择器不可用时，文本回退必须先提供两种结果，再提供三个自动化选项，而不是四个演示的扁平列表。在同一次编辑中，为每张卡片更新 last_changed_by、last_changed_at 和 version
