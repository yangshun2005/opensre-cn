# 测试规范原则

`tests/e2e/` 实时端到端测试的原则。本目录中的真实测试夹具就是标准用法示例——本文件只陈述规则，不涉及代码。

## 1. 真实端到端测试：禁止 Mock

测试必须使用真实服务和真实基础设施（实时安装器、Grafana Cloud、PostHog、incident.io、Docker 构建）——不得使用 Mock 服务或模拟响应。在这里使用 Mock，只会用人工构造的载荷验证 Agent，而非生产环境的真实产出。

## 2. 关注点分离：纯业务逻辑

测试驱动的任何工作负载代码都必须与测试编排/可观测性代码隔离——它应当看起来像真实的客户代码，这样测试验证的是针对类生产系统的行为，而非被插桩的系统。反模式：将测试基础设施混入业务逻辑。

## 3. 按环境门控，缺失时明确跳过

实时测试套件需预先声明所需的凭据/环境（参见 `grafana_validation/env_requirements.py`），缺失时以明确原因跳过，这样没有密钥的 CI 保持通过，同时不会掩盖有凭据运行时的失败。
