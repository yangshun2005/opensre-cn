# 遥测调查基线（草稿）

在修改 `core.telemetry.investigation.investigate` 入口的提示词、输出格式或证据访问方式之前，先测量其现有表现。生成过程使用真实的脱敏、输入预算、无工具合成和可终止的模型进程。它不运行 watch、不连接 ClickHouse、不发送通知。

## 基线状态

- 十二个**合成的、由 agent 编写**的 fixture；全部等待 SRE 审核。它们是提议的评分预期，不是独立验证过的基准真值。
- 本草案未建立任何实时调查员得分或人工/评判员一致性。单元测试使用注入的调查员/评判员，不发起模型调用。
- 报告仍为自由文本。确定性检查仅验证保留的检测器计数前缀；不验证模型文本中的每个计数、引用是否存在或因果支撑。这些需要下一阶段的结构化报告。语义得分仅供参考，尚无发布阈值。

## 用例设计与审核

`cases.json` 将调查员的 `incident` 与仅评估器可见的 `expectations` 分开。用例 ID、类别、家族、划分或评分标签均不进入生产调查员。其脱敏输入载荷原样保留在运行产物中。评分器看到该载荷和评分预期；它从不获取额外遥测或调用调查员。

四个分组分别覆盖明确的故障机制、证据不足、误导性样本/冲突消息、不可信/噪声遥测。认证用例对在第二个用例中增加了决定性证据：仅凭无效 token 不能证明过期，但关联的验证器日志可以证明所选请求的过期。样本证据永远不能证明所有已检测故障中的普遍性。

开发/留出划分按事件家族分组。留出用例对仓库可见；将其排除在提示词调优之外，并记录使用时间。这个微小的合成留出集不是生产准确率估计。

SRE 应在将 `review_status` 设为 `sre_reviewed` 之前，审核每个用例的观察、最强有据结论、无支撑结论和可接受的下一步检查。候选原因可以作为明确的未知项或下一步检查提及；不要通过禁用词匹配来评分。

## 生成基线报告（实时，需主动启用）

在仓库根目录运行，需安装正常的 OpenSRE 环境，并通过现有 OpenSRE 模型设置配置 API 模型。生产调查员拒绝 CLI 模型后端。此命令消耗模型配额，每次运行最多耗时生产合成截止时间，且从不在 pytest 或普通 CI 中自动运行。

```bash
uv run python -m tests.core.telemetry.evaluation.runner generate \
  --case auth_rejection --repeats 1 --output work/triage-smoke.jsonl

uv run python -m tests.core.telemetry.evaluation.runner generate \
  --split development --repeats 3 --output work/triage-baseline.jsonl

uv run python -m tests.core.telemetry.evaluation.runner summarize \
  work/triage-baseline.jsonl
```

选项：`--cases` 默认为内置数据集；`--case` 可选地选择精确 ID；`--split` 默认为 `development`（`holdout`/`all` 需显式指定）；`--repeats` 默认为三且必须为正；`--output` 必填且不得已存在。选择留出用例时需选择兼容的划分。

JSONL 清单记录修订版本、工作区脏状态、数据集/源哈希、合成函数源码（含其提示词）、提供方、父侧解析的模型 ID、Python 版本和生产默认生成策略。生成设置保持生产默认值；当前入口不暴露确切的提供方请求参数、返回的模型身份、token 用量或价格。这些记录为不可用而非估算。子进程会重新验证提供方，但父模型 ID 不能证明提供方别名实际服务的模型。运行期间保持配置固定。

每次尝试后刷新结果。部分合成回退、抛出的错误、中断/缺失的运行均保持可见。摘要/评分可恢复不完整的最终 JSONL 写入，显式标记，并仍拒绝损坏的完整行。任何尝试部分或失败时，生成以非零退出。现有文件永不被覆盖；产物在支持时以仅所有者文件权限创建。将生成的产物放在被忽略的 `work/` 下；不要提交真实遥测或凭据。

## 用 DeepEval 为已保存报告评分（实时，需主动启用）

DeepEval 目前要求 Rich 低于 15，而 OpenSRE 要求 Rich 15 或更新。因此评判器有**独立的锁定 uv 项目**。它读取已保存的 JSONL 产物，不导入任何 OpenSRE 运行时模块。应用锁文件和运行时依赖不变。

通过 DeepEval 支持的提供方设置配置所选评判模型的凭据。`--model` 必填；比较时保持标识符固定。无需 Confident AI 登录。评判模型请求仍会将合成证据/报告/评分标准发送给该模型提供方。下方的遥测退出与模型流量无关。

```bash
DEEPEVAL_TELEMETRY_OPT_OUT=1 uv run --locked \
  --project tests/core/telemetry/evaluation/judge \
  python tests/core/telemetry/evaluation/judge/score.py \
  --runs work/triage-baseline.jsonl \
  --output work/triage-baseline-scores.jsonl \
  --model gpt-4.1
```

示例模型是选择器，不是推荐或已测量的评判器。用相同命令和新输出路径可重新评分而无需重跑调查员。输出文件不得已存在。

两个自定义 G-Eval 指标返回归一化得分和理由：

1. **证据支撑：** 主张源自可用证据；因果主张、群体性主张和恢复声明需要支撑。
2. **诊断有用性：** 最强有据发现、重要未知项和有针对性的下一步检查。泛泛弃权在决定性用例上失分。

评分器在评判前读取并哈希一个输入快照。其 JSONL 输出以源哈希（评分标准身份）、DeepEval 版本、评判模型选择器、生成清单和输入快照哈希开头。每个完成或失败的指标立即刷新，随后是每次尝试的结果；最后一行是摘要。中断保留已完成工作，无需覆盖。本草案无自动恢复/合并命令。

每个指标有各自的失败状态。若一个失败，另一指标的得分和理由仍可用。意外的评判失败也保留已收到的指标。每用例摘要包含已评分的 `n`、均值、最小值和最大值；指标、生成、评判和缺失运行计数分开。失败永不被赋予满分或隐藏在总体均值中。部分报告可获得语义得分，但仍计为部分执行。非零退出表示生成/评判不完整，而非语义阈值失败。

在信任这些得分之前，让 SRE 对每个用例的几份好/坏报告排序（包括自信但无支撑和过度含糊的答案），然后比较评判排序并检查分歧。G-Eval 是非确定性的；保留原始报告、评判理由和重复运行。本草案提供评分标准，而非其与 SRE 判断一致的证据。

## 离线检查与迭代

```bash
uv run python -m pytest tests/core/telemetry/test_evaluation.py
```

普通 pytest 检查数据集有效性、家族划分隔离、评估器标签分离、已保存载荷脱敏、重复/篡改运行拒绝、失败核算、快照哈希/截断尾部恢复、中断检查点和重复得分聚合。它不导入 DeepEval 依赖。新测试加入现有默认测试选择；不添加实时 CI 工作流。不要在默认测试套件中放置付费模型调用。

下一步：SRE 审核用例、校准评判器、生成并保留基线 v0，然后在相同证据/模型上比较结构化报告 v1。仅在这些比较之后添加有作用域的工具调用调查员。改进必须按用例展示，并附完成/弃权行为；总是说"未知"的 agent 不能通过避免所有诊断而获胜。
