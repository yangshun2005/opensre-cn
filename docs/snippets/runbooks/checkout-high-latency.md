# 结账高延迟

## 目标

判断结账延迟来自流量、近期部署，还是下游依赖。只有在证据指向某一原因后，才优先采用可回滚的缓解措施。

## 诊断顺序

1. 确认告警时间窗口、环境、区域和受影响的结账实例。
2. 将请求速率、错误率和 p95/p99 延迟与之前的健康窗口对比。
3. 检查延迟升高前刚发生的部署和配置变更。
4. 检查数据库连接饱和度、支付提供商延迟和队列积压。
5. 在存在应用日志和追踪数据时，将单个慢请求在两者间关联起来。

## 决策点

- 如果延迟在某次部署后立即出现，且同一依赖仍健康，通过正常审批流程提出回滚。
- 如果某依赖已饱和，确定其负责人，并通过正常审批流程提出降载或容量变更。
- 如果证据不完整，说明缺少哪个来源；不要推断根因。

## 收尾

报告已执行的检查、观察到的证据、跳过的步骤，以及仍需审批的补救措施。将本文档中的指导与观察到的事实分开记录。
